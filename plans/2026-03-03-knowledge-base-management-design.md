## 1. 概述

本文档描述了企业 RAG 系统的知识库管理功能扩展设计。该功能允许用户在前端界面动态管理多个知识库，每个知识库使用独立的 Milvus Collection 进行数据隔离。

### 1.1 目标

- 支持创建、查看、删除多个知识库
- 支持向指定知识库上传文档
- 支持在问答时切换知识库
- 所有知识库共享全局检索配置

### 1.2 约束

- 使用全局配置（chunk_size、embedding 模型等）
- 每个知识库使用独立的 Milvus Collection
- 文档上传后自动触发向量化流程

## 3. API 设计

### 3.1 创建知识库

```http
POST /api/v1/knowledge-bases
Content-Type: application/json

{
  "name": "产品文档",
  "description": "公司产品相关文档"
}

Response 200:
{
  "id": "kb_001",
  "name": "产品文档",
  "description": "公司产品相关文档",
  "collection_name": "kb_001",
  "created_at": "2026-03-03T10:00:00Z",
  "doc_count": 0
}
```

### 3.2 列出所有知识库

```http
GET /api/v1/knowledge-bases

Response 200:
{
  "knowledge_bases": [
    {
      "id": "kb_001",
      "name": "产品文档",
      "description": "公司产品相关文档",
      "collection_name": "kb_001",
      "created_at": "2026-03-03T10:00:00Z",
      "doc_count": 10
    }
  ]
}
```

### 3.3 获取知识库详情

```http
GET /api/v1/knowledge-bases/{kb_id}

Response 200:
{
  "id": "kb_001",
  "name": "产品文档",
  "description": "公司产品相关文档",
  "collection_name": "kb_001",
  "created_at": "2026-03-03T10:00:00Z",
  "doc_count": 10,
  "documents": [
    {
      "filename": "manual.pdf",
      "uploaded_at": "2026-03-03T10:05:00Z",
      "status": "completed"
    }
  ]
}
```

### 3.4 上传文档

```http
POST /api/v1/knowledge-bases/{kb_id}/documents
Content-Type: multipart/form-data

documents: [file1, file2, ...]

Response 200:
{
  "uploaded": 2,
  "failed": 0,
  "processing": true
}
```

### 3.5 删除知识库

```http
DELETE /api/v1/knowledge-bases/{kb_id}

Response 200:
{
  "message": "知识库已删除"
}
```

### 3.6 查询指定知识库（更新现有 API）

```http
POST /api/v1/query
Content-Type: application/json

{
  "question": "如何使用产品？",
  "kb_id": "kb_001",
  "top_k": 5,
  "use_rerank": true
}
```

## 6. 核心流程

### 6.1 创建知识库流程

```
用户输入信息
    │
    ▼
验证名称唯一性
    │
    ▼
生成唯一 ID (kb_xxx)
    │
    ▼
创建 Milvus Collection
    │
    ▼
保存元数据到 JSON
    │
    ▼
返回成功响应
```

### 6.2 上传文档流程

```
用户上传文件
    │
    ▼
保存到临时目录
    │
    ▼
DocumentLoader 加载
    │
    ▼
TextSplitter 分块
    │
    ▼
EmbeddingService 向量化
    │
    ▼
VectorRetriever 存储
    │
    ▼
更新元数据
    │
    ▼
返回处理结果
```

### 6.3 问答查询流程（更新）

```
用户提问 + 选择知识库
    │
    ▼
从指定 Collection 检索
    │
    ▼
LLM 生成答案
    │
    ▼
返回结果 + 来源
```

## 7. 错误处理

### 7.1 错误码

| 错误码 | 说明 |
|-------|------|
| 400 | 请求参数错误（如名称冲突） |
| 404 | 知识库不存在 |
| 500 | 服务器内部错误 |

### 7.2 处理策略

1. **知识库名称冲突**: 返回 400，提示更换名称
2. **文档上传失败**: 返回部分成功信息，列出失败文件
3. **Collection 创建失败**: 自动回滚，清理元数据
4. **向量存储失败**: 记录失败文档，支持重试
5. **删除不存在**: 返回 404，但不影响系统运行
